单选题
Action Validity 与 Meaningful Step Ratio 的核心区别是什么？
A
Validity 检查动作是否合法，Meaningful 检查是否真正改变了世界状态
B
Validity 只检查格式，Meaningful 检查语法正确性
C
两者完全相同，只是不同论文的叫法不同
D
Validity 是过程指标，Meaningful 是结果指标
解析

A 正确。Validity = 动作格式合法 + 前提满足（如材料充足、坐标合法）。Meaningful = 动作不仅合法，还真正改变了世界状态。例如：在已有方块的位置再放一个方块 → Valid（格式对）但 Meaningless（世界没变）。

单选题
在 Goal-state Diff 中，Precision 指标的主要作用是防止什么行为？
A
Agent 故意遗漏目标方块
B
Agent 放置错误的方块类型
C
Agent "铺满全图"来刷 Recall 分数
D
Agent 在终局时破坏已有结构
解析

C 正确。Precision = correct / (correct + extra)。如果没有 Precision，Agent 可以策略是"在所有空地放满石头"——这样 Recall≈100%（目标位置肯定被覆盖了），但实际上造了一堆多余的方块。Precision 惩罚多余的方块。

以下哪项最能体现"传统二元 Success Rate 指标的区分度不足"？
A
SR=0% 但 Progress=90% 的 Agent 与 SR=0% 但 Progress=10% 的 Agent 被同等对待
B
SR 计算需要多次运行，消耗更多计算资源
C
SR 无法衡量 Agent 的安全性
D
SR 只适用于游戏场景，不适用于通用任务

A 正确。这是 GameWorld 实验的核心发现：SOTA 模型在 TextQuests / VisEscape 上完整通关率为 0，但许多模型能达到 ~90% progress。如果只看 SR，这些 Agent 和"一上来就失败"的 Agent 没有区别——这就是区分度不足。

单选题
ODYSSEY 论文提出的"Critic 降级设计"核心思想是什么？
A
让 LLM Critic 拥有更高权限，可以强制终止 Agent 的错误行为
B
将 LLM Critic 从"最终裁判"降级为"语义解释器"，最终判断交给状态断言
C
完全移除 LLM Critic，只用规则引擎做验证
D
让多个 LLM Critic 投票决定，降低单一模型的误判率
解析

B 正确。ODYSSEY (IJCAI 2025) 的核心洞察：LLM Critic 的误判会沿规划链累积——第 3 步的 critic 说"对"，后续所有步骤都基于错误前提继续。解决方案不是移除 Critic，而是降级：Critic 负责语义理解，最终判断交给可计算的状态断言。

C

单选题
在 Harness 自评的 Net Benefit 框架中，以下哪种情况说明该 Harness 组件不值得部署？
A
Net Benefit < 0（提升的分数不足以覆盖额外成本）
B
Δscore = 0（Harness 对性能没有影响）
C
extra_latency > 1 秒（任何延迟增加都不可接受）
D
false-block rate > 0（存在任何误拦都说明设计失败）
解析

A 正确。Net Benefit = Δscore − λ·cost。当 Net Benefit < 0 时，说明 Harness 带来的性能提升不足以覆盖其 token/延迟/误拦等成本。B 只是没有收益但也没有成本；C 和 D 的绝对阈值取决于具体应用场景。

A
Agent 的公开声明总是与最终行动完全一致
B

C

A

B
LLM-as-judge 的能力上限直接约束了评测的有效性
C
使用同源模型（如 GPT-4 评判 GPT-4 Agent）会产生系统性偏置
D
可状态化判断应优先使用 LLM-as-judge 而非状态断言
E
Judge Consistency 可用 Cohen's κ 量化，κ ≥ 0.8 为质量门槛
F

多选题
以下哪些论文/工作明确指出了"Verifier / 评测自身也会被过拟合"的风险？
A
RepoST：RL reward hacking 风险
B
AFlow：搜索式编排的评测过拟合
C
AutoForge：环境 bug 被 Agent exploit
D
ACE：AppWorld test-challenge split 验证不过拟合
E
GameWorld：Minecraft Clone 的 progress 指标
F
SafeArena：四态合规评估
解析

正确答案：A、B、C、D。E（GameWorld）提出了 Progress 指标，但并未聚焦 verifier 过拟合；F（SafeArena）关注安全合规而非 verifier 被 hack。A/B/C 是原文明确列出的三个 verifier 被过拟合的案例；D 是防护措施（用 held-out 验证不过拟合）。

判断题
Success Rate 越高的 Agent，其 Normalized Progress 也一定越高。
解析

错误。SR 是二元指标（0/1），Progress 是连续指标。反例：Agent 在 100 次运行中 1 次完美通关（SR=1%）、99 次完全失败——但另一个 Agent 每次都能达到 90% 进度却从未通关（SR=0%, Progress=90%）。前者 SR 高但 Progress 可能很低。两者衡量的是完全不同的维度。

判断题
Precision 和 Recall 在 Goal-state Diff 中总是同步升降的——Precision 高意味着 Recall 也一定高。
解析

错误。Precision 和 Recall 之间存在 trade-off（权衡）。Agent "铺满全图"时 Recall≈100%（目标位置都被覆盖了）但 Precision 很低（大量多余方块）。反之，Agent 只放极少量方块且都正确时 Precision≈100% 但 Recall 很低（大量目标未完成）。需要 F1 来综合两者。

判断题
Normalized Progress 中使用 q^max（历史最高进度）而非终局进度，是为了防止 Agent 在接近完成时不小心破坏结构而导致能力被低估。
解析

正确。这是 GameWorld 论文的核心设计之一。例如：Agent 建造了 90% 的房子，最后一步误拆了一个方块——终局进度 = 0%（完全失败），但 q^max = 90%。用 q^max 能更准确地反映 Agent 的真实能力上限，避免"临门一脚"的偶然破坏导致系统性低估。

判断题
Action Validity = 100% 意味着 Agent 的所有动作都既有意义（meaningful）又推进了任务。
解析

错误。Validity 只检查"动作是否合法"（格式正确、前提满足），不检查是否"有意义"。反例：Agent 反复执行"移动到已所在位置"——动作合法（坐标在范围内），但世界状态未改变，因此是 Valid 但不是 Meaningful。Meaningful Step Ratio 才是衡量"真正推进了任务"的指标。

判断题
Harness 组件设计得越复杂（如加入多层记忆、反思、规划模块），其 Net Benefit 就一定越高。
解析

错误。Net Benefit = Δscore − λ·cost。复杂 Harness 可能提升准确率，但同时消耗更多 token、增加延迟、提高误拦率。如果 Δscore = +3% 但成本使 λ·cost > 3%，Net Benefit 为负——此时更简单的 Harness 反而更优。这是 Harness Engineering Survey 的核心观点：不是"越多越好"，而是"性价比最高才好"。

判断题
在评估 Agent 时，LLM-as-judge 应该优先于状态断言（State Assertion），因为 LLM 的理解能力更强，可以处理更复杂的评判逻辑。
解析

错误。统一判断原则明确规定："可状态化的判断一律走断言，judge 仅兜底无 ground-truth 的维度"。状态断言（如"坐标(5,3)是否有石头方块"）是精确、可复现、不可 hack 的；LLM-as-judge 有假阳性/假阴性、同源偏置、能力上限约束等问题。LLM 只应在"美观度""创意性"等主观维度上作为兜底方案。
