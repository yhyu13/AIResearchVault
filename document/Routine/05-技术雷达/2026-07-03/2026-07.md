## P0 — 立即学习（Adopt）

> 已经成熟、你应该投入精力的技术。目标：达到行业前 20% 水平。

| 技术 | 主题 | 为什么 | 投入计划 |
|------|------|--------|----------|
| **MCP (Model Context Protocol)** | 标准化的 LLM Tool Use 协议 | Anthropic 主导的开放标准，已获 OpenAI、Google、Microsoft 支持。2025-11-25 规范引入 Tasks 异步原语（SEP-1686）与 CIMD 认证，并已移交 Linux Foundation 托管；SDK 月下载量达 9700 万。但需注意 tool poisoning 攻击面（MCPTox, AAAI 2026）与全量工具描述注入的 ~55k token 上下文成本，应按 curated allowlist 使用。 | 阅读 MCP 规范 2025-11-25 版；实现一个自定义 MCP server（如连接笔记检索）；建立 allowlist 并评估 tool poisoning 防护 |
| **LangGraph / LlamaIndex Workflows** | Agent 编排与状态机框架 | LangGraph 提供了基于图结构的 agent 工作流编排，支持循环、条件分支、人机协同。LlamaIndex 的 Workflows 提供了类似的声明式 agent 管道。两者已成为构建复杂 agent 的事实标准。 | 用 LangGraph 实现一个"论文阅读助手"——自动检索论文 → 提取关键公式 → 生成笔记草稿 |
| **Vector DB + Embedding 模型** | Agent 长程记忆的存储与检索 | 双首选：**pgvector (+pgvectorscale)**（50M 向量规模 99% recall 下 471 QPS，对比 Qdrant 41 QPS）与 **Qdrant**（强在 filtered ANN 与多租户场景）。Embedding 推荐转向自托管 **Qwen3-Embedding / BGE-M3**（MTEB 70.58，超越 OpenAI text-embedding-3-large 的 64.52，成本约 1/25）。RAG 及格线：hybrid（BM25 + dense + RRF k=60）+ cross-encoder reranker（较裸 dense +17pp 精度）。 | 将笔记库向量化（Qwen3-Embedding 自托管）；构建 hybrid + reranker 的 RAG 管道；评估 pgvectorscale 与 Qdrant 在数学公式文本上的检索准确率 |
| **vLLM / SGLang / TensorRT-LLM** | LLM 推理加速引擎 | 对部署本地 agent（而非仅调用 API）至关重要。vLLM 的 PagedAttention 和 continuous batching 是生产级推理的基础；SGLang 的 RadixAttention 前缀复用在 agentic / tool-calling 负载下 TTFT 最优。两者按负载画像选型。 | 本地部署 Qwen3-32B 或 Llama-4-Scout；在论文问答与 tool-calling 负载上分别对比 vLLM 与 SGLang 的 TTFT / 吞吐 |
| **Agent Skills** | 技能封装的开放标准 | Progressive disclosure 的 skill 封装开放标准，2025-12 起 OpenAI / Google / Cursor 相继兼容，skill library 模式完成工业化。对 agent 能力模块化与复用是基础设施级技术。 | 将笔记库中的可复用流程封装为 skill；评估 progressive disclosure 对上下文成本的节省 |
| **DSPy** | 声明式 LLM 编程框架 | 用编程范式替代 prompt engineering，自动优化 LLM 调用链。对构建可复现、可优化的 agent 推理管道有价值。 | 用 DSPy 实现"论文摘要 → 关键公式提取 → 推导验证"的 agent 管道 |
| **DeepSeek-R1 / DAPO** | 纯 RL 激发推理能力 | DeepSeek-R1 (Nature 2025) 证明纯 RL 无需 SFT 即可激发推理能力；DAPO 四项改进将 GRPO 推向生产级稳定训练。 | 精读 R1 论文的 GRPO 推导部分；复现 DAPO 的 Clip-Higher 和 Token-Level Loss 实现 |
| **OpenRLHF / verl (HybridFlow)** | 开源 RLHF 训练框架 | OpenRLHF 是首个 Ray+vLLM 分布式 RLHF 框架；verl 提供灵活高效的 RLHF 流式实验管理。社区基础设施成熟。 | 阅读源码，理解分布式训练中的通信优化；评估对 agent 训练的可扩展性 |

## P1 — 持续关注（Trial）

> 有潜力、值得实验的技术。目标：了解原理、跑通 Demo。

| 技术 | 主题 | 为什么 | 实验计划 |
|------|------|--------|----------|
| **GraphRAG** | 基于知识图谱的 RAG 增强 | 微软研究院开源。将非结构化文本提取为知识图谱，支持跨文档的推理式检索。对大量论文笔记的关联检索有潜在价值。 | 用论文集合构建一个 GraphRAG 原型；对比传统 RAG 的检索质量 |
| **AutoGen / CrewAI** | Multi-agent 协作框架 | AutoGen 已进入维护模式（Microsoft Agent Framework 于 2026-04 GA，合并 AutoGen + Semantic Kernel）；CrewAI 存在 +11% 的 token 开销。选型建议转向 LangGraph 1.0（2025-10 发布，durable execution）/ LlamaIndex Workflows / OpenAI Agents SDK / Google ADK。 | 存量项目维持运行；新项目改用 LangGraph 1.0 或 OpenAI Agents SDK 搭建"论文研读小组"原型 |
| **GRPO-based Tool-Use RL**（ToolRL） | 工具使用能力的 RL 训练 | ToolRL（arXiv:2504.13958）提出细粒度 reward 分解（格式 / 参数名 / 参数值分项奖励），为 tool-use RL 提供了比 outcome-only 更稳定的训练信号。 | 精读 ToolRL 的 reward 分解设计；在小型 tool-calling 任务上复现 GRPO 训练 |
| **Speculative Decoding / MTP** | 推理延迟优化 | 草稿模型 / Multi-Token Prediction 在低并发、延迟敏感场景收益明确；但高并发下收益坍缩（arXiv:2510.22876 实测证据）。限定适用场景，不作为通用加速手段。 | 在低并发单请求场景实测 speculative decoding 的延迟收益；验证高并发下的坍缩点 |
| **Prefill-Decode Disaggregation** | 推理服务架构 | 将 prefill 与 decode 阶段拆分部署，分别匹配 compute-bound / memory-bound 的硬件画像，提升 agentic 长上下文负载的整体吞吐与 SLO 达成率。 | 阅读 DistServe / Splitwise 等方案；评估在本地多卡环境的部署可行性 |
| **ACE (Agentic Context Engineering)** | 上下文自进化框架 | ICLR 2026。将上下文视为进化 playbook，Generator→Reflector→Curator 模块化流程，+10.6% agent 基准。 | 阅读 ACE 论文，理解 Grow-and-Refine 约束；实现简化版 ACE 循环 |
| **Agent-R1 / RollArt** | 端到端 agent 训练系统 | Agent-R1 端到端 RL 训练强大 LLM agent；RollArt 分离式基础设施扩展 agentic RL，1.35-2.05x 训练加速。 | 跟踪代码开源进展；评估分离式架构对 agent 训练的实际收益 |
| **MARTI** | 多 agent 强化训练框架 | ICLR 2026。AT-GRPO 算法支持独立资源池的并发 on-policy 训练。 | 理解多 agent 训练中的信用分配问题；评估与单 agent 训练的效率对比 |
| **ACT (Agentic Critical Training)** | 批判式训练 | arXiv 2026。通过批判式反馈提升 agent 的推理质量。 | 阅读论文，理解批判信号与奖励设计的结合方式 |
| **AReaL** | 大规模异步 RL 系统 | Inclusion AI。1→1000 GPU 可扩展，完全异步消除同步瓶颈。 | 评估异步训练对 agent 长 horizon 任务的稳定性影响 |
| **Mem0 / AgentSys** | 生产级长期记忆系统 | Mem0 提供实体关系图谱与动态记忆更新；AgentSys 提供安全动态层次记忆。 | 对比两者的记忆检索策略；评估在长对话中的遗忘率 |

## P3 — 暂时观望（Hold）

> 不成熟或已过时的技术。目标：了解为什么被替代。

| 技术 | 主题 | 为什么 | 替代方案 |
|------|------|--------|----------|
| **纯 Prompt Engineering 无结构化工作流** | 早期 GPT-3 应用风格 | 复杂任务中纯 prompt 无法保证一致性；ReAct/CoT 证明需要显式推理结构。 | 使用 ReAct / LangGraph / DSPy 等结构化框架 |
| **单 Agent 解决所有问题** | 早期 AutoGPT/BabyAGI 风格 | 单 agent 在长时程任务中上下文爆炸、错误累积；多 agent 协作成为主流。 | 使用 AutoGen / CrewAI / MetaGPT 等多 agent 框架 |
| **纯向量检索记忆（无分层管理）** | 早期 RAG 应用风格 | 纯向量检索缺乏时间感知、重要性排序、遗忘机制；MemGPT/Generative Agents 证明需要分层架构。 | 使用 Mem0 / AgentSys / A-Mem 等分层记忆系统 |
| **静态 Benchmark（无更新）** | HumanEval / MBPP 风格 | 数据污染导致评估失效；GPT-4 在 HumanEval 上接近 100% 饱和。 | 使用 LiveCodeBench / SWE-rebench / SWE-Universe 等动态评估 |
| **Outcome-Only 评估** | 早期 SWE-bench 风格 | 无法区分正确推理和记忆/猜测；无法诊断 agent 失败模式。 | 使用 ToolSandbox / PRM / ResearchRubrics 等过程级评估 |
| **SFT 后必须接 RLHF** | 传统对齐范式 | DeepSeek-R1 证明纯 RL（无需 SFT）即可激发推理能力，涌现长思维链。 | 采用 R1-Zero 风格的纯 RL 训练或 SFT+RL 混合 |
| **AutoGen / AG2**（新项目） | Multi-agent 框架选型 | AutoGen 已进入维护模式（被 Microsoft Agent Framework 吸收）；AG2 处于 Beta 重写阶段。新项目无采用理由。 | 新项目使用 LangGraph 1.0 / OpenAI Agents SDK / Google ADK |
| **无网关直接暴露 stdio MCP Server** | MCP 部署反模式 | 审计实证约 7000 个 MCP server 直接暴露在公网，无认证无网关，构成严重攻击面（配合 tool poisoning 风险）。 | 所有 MCP server 经网关 + 认证（CIMD）暴露，按 curated allowlist 管理 |
| **pass@1 单点分数作为选型依据** | 模型 / agent 评估反模式 | 单次 pass@1 方差大：pass^8 衰减显著，multi-turn 场景还有 5–10 点落差，单点分数无法支撑选型决策。 | 使用 pass^k / 多次采样均值 + multi-turn 基准做选型 |
| **OpenAI text-embedding-3 / Cohere Rerank 3.5** | 闭源 embedding / rerank API | 已被开源全面超越：Qwen3-Embedding MTEB 70.58 vs text-embedding-3-large 64.52，自托管成本约 1/25；开源 cross-encoder reranker 同样领先。 | 自托管 Qwen3-Embedding / BGE-M3 + 开源 cross-encoder reranker |
| **裸 dense 单路检索 RAG** | RAG 检索反模式 | 已知反模式：缺 BM25 词法信号与重排序，精度显著低于 hybrid + reranker（+17pp）。 | hybrid（BM25 + dense + RRF k=60）+ cross-encoder reranker |

## 专题深潜：AI 3D Video Generation

> 与用户日常工作直接相关，独立演变史报告见：
> [`history_AI_3D_Video_Generation_演变史.md`](history_AI_3D_Video_Generation_演变史.md)

### 一句话定位
Google Veo 3/3.1、Runway Gen-3 Alpha、Captain Safari (pose-aligned 3D world memory) 等已实现 text/image-to-video 的 3D 一致性生成。2026 年向 real-time 和可交互方向演进。对游戏而言，意味着未来可能用生成式模型替代传统渲染管线的一部分。

### 关键里程碑速览

| 年份 | 事件 | 意义 |
|------|------|------|
| 2020 | NeRF (Mildenhall et al., ECCV) | 神经辐射场革命，首次用 MLP 编码连续 3D 场景 |
| 2022 | Instant-NGP (Müller et al., SIGGRAPH) | 多分辨率哈希编码，训练速度从小时级降到分钟级 |
| 2023 | 3D Gaussian Splatting (Kerbl et al., SIGGRAPH) | 显式高斯表示，渲染速度 100-200× 于 NeRF，开启实时神经渲染 |
| 2024 | Sora (OpenAI)、Veo (Google) | 视频生成模型突破时长和一致性瓶颈 |
| 2025 | Captain Safari、DriveGen3D | pose-aligned 3D world memory、动态驾驶场景 3D 生成 |
| 2026 | Veo 3.1、Runway Gen-3 Alpha、实时交互方向 | 3D 一致性 + 可控性 + 向实时逼近 |

### 与 AI Agent 的交集
- **共同问题**：采样（视频生成采样 latent，agent 决策采样动作）、可微分渲染（梯度反向传播）
- **互补方向**：AI 生成可作为 agent 的感知输入（生成场景 → agent 理解），或替代部分传统渲染环节
- **技术债**：当前生成模型的物理正确性仍不足，agent 的推理严谨性短期内不可替代

### 建议行动
- 跟踪 Veo 3.1、Runway Gen-3 的 API 更新
- 关注 world engine（如 Captain Safari）的 camera-controlled 生成质量
- 阅读独立演变史报告（~8,500 字）了解完整技术脉络

## 专题深潜：AI-Native Game / World Models

> 与用户日常工作直接相关，独立演变史报告见：
> [`history_AI_Native_Game_World_Models_演变史.md`](history_AI_Native_Game_World_Models_演变史.md)

### 一句话定位
Oasis (500M 参数实时生成 Minecraft-like 世界)、Genie 3 (DeepMind, 720p@24fps 可交互生成世界)、DIAMOND (diffusion world model 训练 agent)、NVIDIA Cosmos (物理感知的 world foundation model)。2026 年被认为是 AI-native game 元年。可能从根本上改变游戏内容生成方式。

### 关键里程碑速览

| 年份 | 事件 | 意义 |
|------|------|------|
| 2018 | World Models (Ha & Schmidhuber, NeurIPS) | 首次用 VAE-MDN-RNN 学习 compact world representation，agent 在"梦境"中训练 |
| 2019 | AI Dungeon | LLM 驱动无限叙事，验证生成式交互体验的可行性 |
| 2020-2021 | Dreamer/DreamerV2/V3 (RSSM) | 隐态动力学模型，model-based RL 的里程碑，world model 从概念到可训练 |
| 2023 | Voyager (NeurIPS) | LLM 驱动的 Minecraft agent，自动课程 + 技能库 + 自验证循环 |
| 2024 | Genie (DeepMind, 11B)、GameNGen、DIAMOND | world foundation model 诞生；diffusion model 实时生成 DOOM；diffusion world model 训练 agent |
| 2025 | Genie 3 (720p@24fps)、NVIDIA Cosmos、Matrix-Game | 可交互世界生成达到消费级分辨率；物理感知的 world foundation model |
| 2026 | "AI-native game 元年"、on-device inference (RTX 50 / PS6) | 世界模型从研究走向产品，端侧推理成为可能 |

### 与 AI Agent 的交集
- **生成 vs. 推理**：传统 agent（感知 → 推理 → 行动）vs. 世界模型（action/condition → latent → image），后者跳过了显式推理但提供了丰富的环境反馈
- **混合架构机会**：world model 生成 coarse 场景 + agent 做精细决策，或 world model 提供初始策略分布（类似策略初始化）
- **性能瓶颈**：当前 world model 推理成本仍高（~50-200ms/帧），距离 60fps 有差距；但端侧 AI 芯片（RTX 50 Tensor Core、PS6 NPU）正在缩小差距
