拖拽填空 Q2
BM25 公式中的两个关键参数：
控制词频饱和度（值越高对高频词越敏感），
控制文档长度归一化（0 表示不归一化，1 表示完全归一化）。
k₁ b α k IDF avgdl
解析

✅ 正确答案：k₁ = 1.5，b = 0.75

❌ 错误选项说明：

• α：这是 RRF 融合时的权重参数，不是 BM25 的参数

• k：这是 RRF 的平滑常数（默认 60），不是 BM25 参数

• IDF：是逆文档频率，属于 BM25 的组成部分但不是可调参数

• avgdl：是平均文档长度，是计算过程中的统计量而非超参数

拖拽填空 Q3
RRF 融合公式中， 是平滑常数，
其作用是防止 的文档分数差异过大。
k=60 低排名 高排名 α=0.5 top-k P99
解析

✅ 正确答案：k=60，低排名

RRF 公式：score(d) = Σ 1 / (k + rank_r(d))

• k=60 是平滑常数，防止排名靠后的文档分数差异过大，保证对排名 1-100 的文档都有区分度

❌ 错误选项说明：

• α=0.5：这是加权融合的权重参数，RRF 是无参数融合，不需要 α

• 高排名：高排名文档（如第 1、2 名）的分数差异本来就大，不需要平滑

拖拽填空 Q4
评估检索效果的三个核心指标：
衡量「找全」的能力，
衡量把最相关文档推到顶部的能力，
同时衡量「找全」和「排对」。
Recall@k MRR nDCG@k P99 延迟 绝对提升 Δ F1 Score
解析

✅ 正确答案：Recall@k → MRR → nDCG@k

• Recall@k：只关心「找没找全」，不关心「排得对不对」

• MRR：只关注第一个相关文档的排名，对 RAG 场景极其重要（通常只取 top-3 送入 LLM）

• nDCG@k：同时衡量「找全」和「排对」，是信息检索领域最全面的单指标

❌ 错误选项说明：

• P99 延迟：衡量系统响应能力，不是检索质量指标

• 绝对提升 Δ：是实验对比指标，不是核心检索质量指标

单选题 Q5
为什么两阶段检索需要「粗排 + 精排」？
解析

✅ 正确：B

Bi-Encoder 把 query 和 doc 分别编码，只需一次点积，速度快但精度有限；Cross-Encoder 拼接输入后过 Transformer，精度高但时间复杂度为 O(N·L²)，无法直接处理大规模文档。

❌ 错误：

• A：因果倒置，Bi-Encoder 精度低于 Cross-Encoder

• C：Cross-Encoder 无法直接处理百万级文档，每次评分都要过完整模型

• D：两者复杂度完全不同，Bi-Encoder 是 O(N·d)，Cross-Encoder 是 O(N·L²)

单选题 Q6
实验中 FAISS 使用哪种索引来实现 Cosine 相似度搜索？
解析

✅ 正确：C

代码中明确注释："FAISS 没有原生 Cosine 索引，先 L2 归一化向量，再用内积(IP)等价实现 Cosine"。这是向量检索的常见 trick。

❌ 错误：

• A：FAISS 没有 IndexFlatCosine 这个原生索引

• B：L2 距离和 Cosine 相似度不等价，除非向量已归一化

• D：虽然 IVF 可以加速，但代码中使用的是精确搜索的 IndexFlatIP

单选题 Q7
RRF 融合相比加权平均的优势是什么？
解析

✅ 正确：D

RRF 的核心洞察：不同检索器的分数尺度不可比（BM25 分数无界，Cosine 在 [-1,1]），直接加权会偏向分数范围大的检索器。排名是标准化后的信号，无需校准。

❌ 错误：

• A：因果倒置，RRF 是无参数融合，不需要训练

• B：RRF 分数确实可以排序，但这不是相比加权平均的核心优势

• C：两者效果不同，RRF 在异构检索器融合上通常更稳健

单选题 Q8
实验结果中，哪种配置在 Recall@10 上表现最好？
解析

✅ 正确：A

实验结果表显示：BM25 + Dense (RRF) + Rerank 的 Recall@10 = 0.85，是所有配置中最高的。完整 Pipeline 同时利用了混合检索的召回优势和重排序的精度优势。

❌ 错误：

• B：Dense Only 的 Recall@10 = 0.72，是基线

• C：BM25 Only 的 Recall@10 = 0.61，词法基线最低

• D：Dense + Rerank 的 Recall@10 = 0.81，虽然提升明显但不如完整 Pipeline

单选题 Q9
对于包含罕见术语、缩写、ID 的查询（如 "GPT-4"），哪种检索方式表现更好？
解析

✅ 正确：B

Embedding 对罕见术语、缩写、ID 的语义捕获能力弱，因为这些词在训练语料中出现频率低，向量表示不稳定。BM25 的词法匹配通过精确匹配恰好互补。

❌ 错误：

• A：Dense Retrieval 对罕见术语的捕获能力弱，不是强

• C：Embedding 无法捕获所有语义，特别是低频词和专有名词

• D：跳过检索会导致幻觉，RAG 的核心价值就是检索增强

单选题 Q10
Cross-Encoder 的 max_length=512 参数限制的是什么？
解析

✅ 正确：C

代码注释明确说明："max_length=512: Cross-Encoder 的输入长度限制，query+doc 拼接后不能超过此长度"。Cross-Encoder 将 query 和 document 拼接后一起输入 Transformer，所以限制的是拼接后的总长度。

❌ 错误：

单选题 Q11
MRR 指标的局限性是什么？
解析

✅ 正确：D

MRR 的定义是首个相关文档排名的倒数均值。如果某个查询有 5 个相关文档，MRR 只关心第一个出现在哪里，后面的 4 个完全不影响分数。

❌ 错误：

• A：这是 nDCG 的局限性，不是 MRR 的

• B：MRR 不依赖于 k 的选择，因为它只看第一个相关文档的位置

• C：这是 Recall@k 的局限性，不是 MRR 的

单选题 Q13
P99 延迟指标的局限性是什么？
解析

✅ 正确：B

P99 的定义是第 99 百分位的延迟值。100 个查询中 1 个慢查询就会显著拉高 P99。它忽略了延迟分布的形状（比如是均匀分布还是长尾分布）。

❌ 错误：

• A：因果倒置，P99 对尾部异常值非常敏感

• C：P99 正是用来衡量「最坏情况」的响应能力

• D：P99 特别适合线上服务配置超时，不是只适用于离线

✓ 正确

解析

判断题 Q24
Bi-Encoder 和 Cross-Encoder 的计算复杂度相同，都是 O(N·L²)，分阶段检索只是工程上的习惯做法。
✓ 正确
✗ 错误
解析

✅ 错误 — 这是常见误解！

Bi-Encoder 的时间复杂度是 O(N·d)（d 是向量维度），Cross-Encoder 是 O(N·L²)（L 是序列长度，Transformer 自注意力是 O(L²)）。两者复杂度完全不同，分阶段检索是算法层面的必要设计，不是工程习惯。

关键洞察：Bi-Encoder 可以预计算文档向量，查询时只需编码 query 一次；Cross-Encoder 每次评分都要重新过完整模型。

✓ 正确
✗ 错误
解析

✅ 错误 — 这是常见误解！

混合检索的互补性表格明确显示：对于纯语义查询（如 "RAG 的原理是什么"），Dense Retrieval 已经很强，BM25 反而弱（因为词不匹配）。混合检索的核心优势在于「长尾/罕见术语」和「同时需要语义+词法」的查询，不是所有场景都更好。

面试陷阱：过度泛化混合检索的优势。需要根据查询类型选择检索策略。
