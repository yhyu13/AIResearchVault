## 关键发现

### 发现 1：AI-Infra 备忘录是本周价值最高的产出

四份文档（`AI-Infra-性能优化全景.md`、`AI_Inference_Infrastructure_Optimization_Landscape.md`、llama.cpp/vLLM 时间线）构成了可以直接指导技术选型的决策参考。包含延迟/吞吐对比、成本-质量权衡、硬件代际数据。对 Agent 系统的 TTFT/ITL/并发/成本等核心体验指标有直接解释力。

**→ 这是 "Agent 为什么慢" 的必备底座。**

### 发现 2：Agent Harness 是高质量教学骨架，但缺少"大脑皮层"

六组件架构（E,T,C,S,L,V）覆盖了 Agent 的感官（Environment）、决策（Task/Agent）、记忆（Context）、安全（Safety）、评估（Verifier）。但：
- `reward = 0.0` —— `environment.py:143`，MDP 数学闭环断裂
- L (Learning) 只有日志，没有学习
- 缺少 Planner（Plan → Execute 层级）、MCP/Tool Use、持久 Memory、Multi-agent

**→ 回答了"骨架是什么"，没有回答"Agent 如何变聪明"。**

### 发现 3：RAG 实验是"可执行的笔记"，不是"可复现的实验"

8 个实验文档知识结构优秀（从基线到 AgenticRAG 的梯度合理），但：
- 全部 8 个实验状态标记为 **"☐ 待开始"**
- 0 个独立 `.py` 文件，代码嵌在 Markdown 代码块中
- 结果表格数据过于整齐，**疑似未真实运行**
- 缺少 Agent 核心集成模式：Tool Use、Streaming、会话感知检索

**→ 实践意义打 50% 折扣。**

### 发现 4：技术雷达在其自声明边界内标杆级，但存在系统性战略盲区

ReSTIR/GI 领域的四象限分类精确到论文章节和代码文件。但：
- **Agent 核心基础设施（MCP、RAG、Vector DB、LLM 推理优化、Multi-agent）完全缺失**
- 四个高价值交叉点未被充分挖掘：
  1. World Model 作为 Agent 训练场
  2. 3DGS 作为 Agent 空间记忆载体
  3. Voyager 架构（自动课程 + 技能库 + 自验证 = Tool Use + Planning + Memory）
  4. ReSTIR 的 Reservoir Sampling ↔ Agent 决策采样的数学同构

**→ ReSTIR Jacobian 推导的每一小时，对直接提升 Agent 能力几乎没有边际收益。**

## 核心判断

> **本周修改有实践意义，但向 Agent 最需要的技能和认知的靠拢程度为「中等偏上」——触及了外围（检索、推理 infra、Agent 骨架），尚未深入核心（Tool Use、Memory 持久化、Multi-agent、Planning、Streaming）。**
>
> **最关键的问题：你的数学严谨性（Jacobian 推导、无偏性证明）是稀缺资产。需要确认这些资产是否配置到了正确的战场——实时 GI 是重要战场，但 Agent 系统的推理基础设施、RAG、Tool Use、Planning 可能是更大且增长更快的战场。**
