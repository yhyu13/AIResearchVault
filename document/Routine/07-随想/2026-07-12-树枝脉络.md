# 随想：Routine 中的树枝脉络

> **写于 W28 复盘之后。**
> 三周前搭起这个 Routine 体系时，以为它会是笔直向上的竹子——每周沿着 01→07 的顺序推进，AI-Tasks 十个主题轮询，像流水线一样匀速积累。
> 三周后回头看，它更像一棵正在抽枝的乔木：有主干，有枝干，有茂密却未必有用的树叶。而问题恰恰在于——我把太多养分给了树叶。

---

## 一、先画树：什么是什么

### 主干——十年磨一剑，不会弯曲的部分

**主干只有一根：数学严谨性，以及在技术领域验证过的「从论文到代码」的穿透能力。**

具体是什么？
- 看到一篇论文，能立刻追问核心推导细节，比如「无偏性证明用了什么 tower property」
- 看到一段代码，能判断权重更新是否符合设计意图
- 看到某个概念，本能地反问 "wtf is X"，直到它精确到公式层或代码层

这根主干不是这周种下的。它是 Vault 里一页页推导养出来的，是 debugger 里一行行跟出来的。**它不随技术潮流弯曲。** 今年热什么、明年冷什么，不影响这根主干的粗细。

> 主干的本质：判断力。判断什么是对的、什么是凑数的、什么只是包装了旧概念的新词。

### 枝干——正在分叉的新生长方向

**目前有两根正在争夺养分的主枝干：**

| 枝干 | 状态 | 与主干的连接 |
|------|------|-------------|
| **AI Agent 系统 / Harness + RAG + Tool Use** | 纤细、新抽、正在试探光照 | 连接点存在但脆弱——W27 复盘发现的「四个交叉点」是嫁接点，但还没有木质化 |

还有几根更细的侧枝：
- **AI Infra 推理优化**：意外长出的强壮侧枝（W27 的 AI-Infra 备忘录质量最高）
- **Game AI / 世界模型**：理论上与主枝干能连接，但目前停留在概念层
- **面试卡牌 / HTML 输出**：不是枝干，是树叶的硬化——后面会讲

> 枝干的核心诉求：**敏锐性**。要判断哪根枝干值得继续长、哪根应该剪除、哪根需要嫁接。

### 树叶——当季繁茂、下季脱落的产出

**树叶是 Routine 中时效性最强、更替最快的部分。** 包括但不限于：

- 每周的实验 Markdown 文档
- 初学者友好的中文注释版教程
- HTML 面试卡牌
- QA 问答对
- 技术雷达的月度更新条目
- 复盘日志里的表格和清单

树叶的价值在于**当季的光合作用**——它们让知识体系看起来茂盛、让学习过程有可见的进度条、让复习时有可以快速翻阅的材料。

但树叶的问题在于：**它们会掩盖枝干的真实生长状况。**

W28 产出了 ~30,000 行新增内容，其中 ~60% 是 HTML。从外部看，这棵树极其茂盛。但翻开土壤看——Agent Harness 的 reward 仍然是 0.0，RAG 实验仍然 13 个里只有 1 个有独立 `.py`，技术雷达的 Agent 基础设施象限仍然空白。

> 树叶的核心法则：**时效性**。当季不摘就会枯黄，但摘太多会耗尽枝干的长高能量。

## 二、问题诊断：养分在哪里错配了

### 错配 1：树叶抢走了枝干的养分

W27 设定止损线时已经意识到这个问题。W28 的结果是止损线被全面突破。

为什么？

因为**生产树叶的边际成本远低于培育枝干**。写一份 200 行的实验 Markdown、做一份 HTML 卡牌、加几行中文注释——这些任务的完成感强、反馈即时、 visibly productive。而修复 Agent Harness 的 reward 函数、把 RAG #01 跑出可运行的 `.py`、推导 Voyager 技能库的 importance sampling 公式——这些任务的摩擦感高、失败风险大、产出前有一段漫长的「看起来什么都没做」的真空期。

**大脑喜欢树叶。** 但枝干才是决定明年这棵树长多高的部分。

### 错配 2：主干的能量没有输送到正确的枝干

这根主干最锋利的部分——无偏性证明、change-of-variables 的精确到代码/公式层——目前主要供给给了图形学这根枝干。

但 W27 复盘提出了一个尖锐问题：「图形学推导的每一小时，对直接提升 Agent 能力几乎没有边际收益。」

这不是说图形学不值得做。而是说，**主干的能量分配需要战略审视。**

有一个被忽视的嫁接点：图形学中的 reservoir sampling 与 Agent 决策中的 importance sampling 在数学上是同构的。这些才是主干能量向新枝干输送的通道——但它们目前只存在于「待做」列表里，没有真正的推导产出。

### 错配 3：枝干的敏锐性被树叶的时效性淹没

技术雷达在 W28 没有完成「Agent 基础设施入四象限」这一战略性动作。680 行调研文档躺在 `research_Agentic_Training...` 文件里，但没有被提炼成雷达的 Adopt/Trial/Assess/Hold 决策。

为什么？因为做雷达决策需要**停下来的思考**——要问自己「MCP 应该放在 Adopt 还是 Trial？」这需要对技术成熟度、自身需求、时间窗口做综合判断。而生产树叶是流水线的、不需要这种停下来的敏锐。

**枝干的敏锐性需要留白，但树叶的时效性要求填满。**

## 三、如何把握三者的节奏

### 主干的方向性——每年审视一次，不要频繁动摇

主干的方向不是每周甚至每月能变的。它是「我是谁」的答案。

目前的判断：
- **数学严谨性 + 实时系统背景** 仍然是不可替代的组合。AI 领域懂 Agent 的人不少，懂 Agent 同时能推导数学细节的人极少。
- **不要放弃图形学**。它是主干的训练场——每篇论文的推导都在锻炼同一种穿透能力，这种能力可以迁移。
- **但要建立「输送管道」**：每做完一个图形学推导，强制问自己「这个推导的数学结构与 Agent/AI 中的哪个问题同构？」

> **主干法则：每年确认一次方向，确认后不因短期潮流摇摆。**

### 枝干的敏锐性——每月修剪一次，果断剪除、果断嫁接

枝干层面的决策需要更频繁的审视。建议以**技术雷达的月度更新**为锚点：

| 动作 | 频率 | 决策标准 |
|------|------|----------|
| **剪除** | 月度 | 连续两个月没有可运行代码/公式产出的方向，降级为 Hold 或删除 |
| **嫁接** | 季度 | 寻找图形学与 AI 的新交叉点，用一篇推导建立连接 |
| **加粗** | 持续 | 选择 1 个方向做「单点打穿」——概念 → 公式 → 代码的完整闭环 |

W29 的「单点打穿」目标是 Voyager 技能库。这个选择是对的：
- Voyager = Tool Use + Planning + Memory，恰好填补了 Agent Harness 缺失的「大脑皮层」
- 技能库的检索可以用 importance sampling 公式化——这是主干能量的直接输送
- 简化实现 <200 行 Python——降低枝干培育的摩擦感

> **枝干法则：月度审视，季度嫁接，接受剪除的沉没成本。**

### 树叶的时效性——每周收割，但设定配额

树叶必须存在。没有树叶，你不知道这周干了什么，复习时没有抓手，面试时没有素材。

但树叶需要**配额管理**：

| 树叶类型 | 配额 | 理由 |
|---------|------|------|
| 实验 Markdown | 每周 ≤1 份，且必须有可运行代码 | W28 的教训：纯文档=技术债务 |
| HTML 卡牌 | 冻结，仅通过自动化脚本生成 | W29 硬止损线 |
| 技术雷达条目 | 月度 1 次更新，不做增量堆砌 | 雷达是决策工具，不是百科全书 |
| 复盘日志 | 每周 1 份，但聚焦「核心判断」 | W27/W28 复盘最有价值的部分是「核心判断」段落 |

**关键原则：树叶必须服务于枝干，而不是遮蔽枝干。**

每生产一份树叶，问自己：
1. 这份文档能帮助我下周写出可运行代码吗？
2. 这份文档能在面试中支撑一个 2 分钟的技术故事吗？
3. 三个月后我还会回看这份文档吗？

如果三个问题的答案都是「否」，这份树叶不该长出来。

> **树叶法则：每周收割，但用「三个月后是否回看」做过滤器。**

## 四、对当前 Routine 体系的结构性反思

### 01-07 体系本身有问题吗？

没有。01→07 的流水线设计是合理的：输入→复现→实验→优化→雷达→复盘→记录。

问题出在**执行时的比例失调**。

| 目录 | 理想状态 | 当前状态 | 偏差 |
|------|---------|---------|------|
| 01-论文阅读 | 精读 + 公式标记 | 框架建得多，精读深推导少 | 偏树叶 |
| 02-算法复现 | 可运行代码 + 测试 | Agent Harness reward=0，RAG 无 .py | 严重不足 |
| 03-实验案例 | 可复现实验 + 真实数据 | 13 个实验仅 1 个有独立代码 | 严重不足 |
| 04-性能优化 | 数据驱动的选型参考 | AI-Infra 备忘录达到标准 ✅ | 达标 |
| 05-技术雷达 | 四象限决策工具 | 图形学详尽但 Agent 象限缺失 | 偏科 |
| 06-复盘日志 | 核心判断 + 止损线 | 质量高但执行率低 | 说得多做得少 |
| 07-随想 | 战略级反思 | 这篇是开篇 | 刚刚开始 |

### AI-Tasks 主题制的问题

十个主题（LLM, RL, Multi-Modal, AIGC, AI-Theory, AI-Training, AI-Optimization, AI-Math, NeRF, time-series）的 Master Index 都已建立，但**全部处于 W1「待开始」状态**。

这是典型的「基础设施投资」陷阱：把架子搭得很漂亮，但没有往里放东西。

建议：**冻结新增主题，直到至少 3 个主题进入 W2 或更深。** 否则这十个空架子本身就是巨大的树叶——看起来体系完整，实际上只是占位符。

## 五、下一步：从「树」到「林」

单棵树的比喻有个局限：它暗示所有养分来自同一根系。但你的背景更像一片**异龄混交林**：

- **成熟林层**：图形学，已经胸径粗壮，不需要天天浇水，每年修修枝、采采果即可
- **中龄林层**：AI Infra 推理优化，意外发现的长势良好的树种，值得加一些抚育
- **幼龄林层**：Agent 系统（Harness + RAG + Tool Use），最需要光照和养分，但目前被成熟林层的落叶遮蔽了

**林业的智慧是：不同龄级的林木需要不同的抚育策略。**

| 林层 | 策略 | 具体动作 |
|------|------|----------|
| 成熟林层（图形学） | 择伐，不是皆伐 | 保持每月 1 篇论文的推导节奏，但不扩展新方向；把推导的「数学结构」作为嫁接材料输送给幼龄林 |
| 中龄林层（AI Infra） | 透光抚育 | 继续完善数据驱动的选型参考；探索与 Agent 系统的直接连接（如 vLLM 的 KV Cache 压缩对长上下文 Agent 的价值） |
| 幼龄林层（Agent） | 除草、松土、定株 | W29 的三条止损线必须解除；单点打穿 Voyager；数学资产强制注入 |

## 六、结语：不要问这周产出了多少行，要问这周树干粗了多少

W27 和 W28 的共同陷阱是：**用产出量（行数、文档数、实验数）代替生长质量（可运行代码数、公式推导数、能力增量）。**

如果 W29 结束时只能记住一件事，应该是这个：

> **树叶的数量是虚荣指标。枝干的粗度才是成长指标。主干的稳定是存在指标。**

这篇随想本身也是树叶——它会在三个月后泛黄。但如果它能影响下周的养分分配，让 Agent Harness 的 reward 不再为 0、让 RAG #01 的 `python main.py` 成功运行、让 Voyager 技能库的 importance sampling 公式落地——那它就完成了树叶的使命：光合作用，然后脱落，把糖分留给枝干。
