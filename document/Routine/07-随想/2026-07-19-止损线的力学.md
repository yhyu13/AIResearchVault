# 随想：止损线的力学——为什么规则止不住损

> **写于 W29 结束当晚。**
> 上一篇随想把 Routine 比作一棵树，诊断出「树叶抢走了枝干的养分」。当时给出的处方之一是「硬止损线」。一周过去了，验收结果：止损线本身也成了一片树叶。
> 这篇要回答的问题不是「我这周又做错了什么」，而是更尖锐的一层：**为什么一条被明确写下、被加粗、被标记为「硬」的规则，在七天内没有产生任何约束力？**

---

## 一、先验收：W29 的力学测量

W28 复盘给 W29 定了三条 P0 止损线和四条硬止损线。逐项测量：

| 规则 | 条款 | 测量值 | 状态 |
|------|------|--------|------|
| P0 | RAG #01 提取为独立 `.py` | 03-实验案例目录下 `.py` 文件数 = **0** | ❌ |
| P0 | Agent Harness reward 非零 | `environment.py:143` 仍为 `reward = 0.0` | ❌ |
| P0 | 建立 `md → html` 自动化脚本 | 不存在 | ❌ |
| 硬止损 | 新增 HTML 文件数 > 0 → 禁止手动建 HTML | 新增 HTML ≥ 3（实验 12、13 双份 + qa-cards） | ❌ 已触发，无人执行罚则 |
| 硬止损 | 无公式推导产出 → 禁止新增纯概念文档 | 有公式产出（Spec Decoding 备忘录）✅ | ✅ 唯一达标项 |

W29 实际产出：实验 12（世界模型生成）、13（Cicero 谈判）、Speculative Decoding 蒙特卡洛框架分析、Agent Memory 性能优化备忘录、Tool Use/MCP 调研简报 + 6 套 qa-cards。以及——**W30 文件夹已经提前建好了**，里面躺着下周的三个实验框架。

产出不少。但三条 P0 全部纹丝不动。这和 W28 的模式**逐帧一致**。

## 二、力学分析：一条不产生力的规则等于不存在

### 止损线是边界条件，但没有约束力

用拉格朗日力学的语言：一个约束要起作用，必须存在对应的**约束力**（constraint force）——当你试图越界时，有一个真实大小的力把你推回来。数学上，约束 \( g(x) = 0 \) 进入动力学方程的方式是引入拉格朗日乘子 \( \lambda \)，力是 \( \lambda \nabla g \)。**没有 \( \lambda \) 的约束只是注释。**

我的止损线全部缺少 \( \lambda \)：

- 「RAG #01 未代码化 → 删除所有未运行实验的 Markdown」——谁来删？我自己。什么时候删？下周复盘时。删的动力是什么？没有。**罚则的执行者和违反者是同一个人，且罚则本身也是一片树叶的生产成本。**
- 「禁止手动创建 HTML」——违反的检测发生在复盘时，即一周后。检测延迟 = 7 天。任何控制工程师都知道，**延迟大于系统时间常数的反馈回路必然振荡或失效**。

一条规则的约束力公式可以写成：

$$F_{\text{rule}} = P(\text{检测}) \times C(\text{惩罚}) \times \frac{1}{1 + \tau_{\text{delay}}}$$

我的三条止损线：检测概率 \(P \approx 1\)（复盘肯定会看），但 \(C \approx 0\)（自我惩罚无执行机制），\(\tau = 7\) 天。乘积恒等于零。**这是规则三连败的数学原因，不是意志力原因。**

### 系统的真实运动方程

观察 W29 的实际轨迹，系统的运动方程更接近：

$$\dot{x} = -\nabla V_{\text{friction}}(x)$$

——沿着摩擦力的负梯度流动，即**最小阻力路径**。各任务的势能面：

| 任务 | 启动摩擦 | 即时反馈 | 完成感 | 净吸引力 |
|------|---------|---------|--------|---------|
| 写新实验文档（12、13） | 低（模板已有） | 即时（行数增长） | 强 | 强 |
| Spec Decoding 备忘录 | 中（要读论文） | 高（公式推导爽感） | 强 | **强** |
| qa-cards | 低（半自动化） | 即时 | 中 | 中 |
| 修 reward=0 | 高（要读旧代码、理解失败语义） | 延迟（调通了才有反馈） | 弱（只是"修复"，不是"产出"） | 弱 |
| RAG #01 提取 .py | 高（要从 200 行文档里逆向出代码） | 延迟 | 弱 | 弱 |

系统精确地流向了势能最低点。**这不是道德失败，这是哈密顿量给定后的唯一解。** 想改变轨迹，要么改势能面（降低硬任务的启动摩擦），要么加约束项（真实的外部力），要么承认这个系统的自然不动点就是「文档无限膨胀」——然后决定要不要接受它。

### 惯性项：提前建好的 W30 文件夹

最能说明问题的一个细节：W30-2026-07-20 目录本周已经创建，里面放好了 14、15、tool_calling 三个实验框架。

这意味着什么？**系统在 W29 中途就已经沿着最小阻力方向加速了**——不仅没做 P0，还提前把下周的「树叶产能」铺好了。这是惯性项 \(m\ddot{x}\) 的直接证据：文档生产的速度没有减，反而在预支。

我对 W28 复盘的「核心判断」段写过：「问题不在于能力，而在于资源配置。」现在修正这个判断：**问题也不在资源配置——资源配置是结果，不是原因。原因是运动方程里没有约束项。**

## 三、一个反例：为什么 Spec Decoding 备忘录完成了

W29 唯一达标的硬止损条款是「公式推导产出」——Speculative Decoding 的蒙特卡洛框架分析真的写出来了，而且质量不低。为什么这条动了？

因为它满足三个条件：

1. **启动摩擦被降过了**：「先猜后验」的采样策略和图形学的 Monte Carlo 框架同构——accept/reject 就是 Metropolis-Hastings 的一步。主干能量有现成的输送管道，推导不是从零开始。
2. **反馈即时**：推公式本身就是反馈，每一步化简都有「对了」的确认信号。
3. **它是 P2 而不是 P0**：没有「必须完成」的压力，反而进入了「想做」的轨道。

这恰好验证了上一篇随想的嫁接假说——**主干（采样理论）向枝干（AI Infra）的能量输送是可行的**。但它也暴露了嫁接假说的边界：它只对「认知迁移类」任务有效，对「工程修复类」任务（修 reward、提取 .py）完全无效，因为后者的摩擦不在认知层，在情绪层——它们是「承认之前没做完」的任务，启动时要先穿过一层心理阻抗。

**结论：势能面改造对认知任务有效；工程任务需要的是外力。**

## 四、机制设计：给止损线装上拉格朗日乘子

如果规则的失效是结构性的，那修复也必须是结构性的。以下不是「下周我要更努力」，而是对约束方程的修改：

### 修复 1：把检测延迟从 7 天压到 0 天

复盘点检测太迟。改为**提交时检测**：Vault 是一个 git 仓库，可以在 commit 时机械检查：

- 新增 `.html` 且不存在对应的生成脚本 → 拒绝或至少大声报警
- 一周内 `02-算法复现` 目录零代码变更 → 周末自动标红

这不是信任问题，是控制论常识：**反馈回路延迟必须小于系统时间常数**。检测不需要智能，需要的是自动化。

### 修复 2：把罚则从「自我执行」改为「预先执行」

「未代码化则删除 Markdown」之所以无效，是因为删除发生在未来、由未来的我执行。改为**预先执行**：

- 新实验文档创建时，先建 `.py` 骨架，文档只能描述代码实际做的事——**文档的存在以代码的存在为前置条件**，而不是反过来用删除来威胁。

这本质上是把不等式约束转化为参数化：不是在 \(g(x) \geq 0\) 外面加惩罚项，而是直接把可行域写进坐标系。

### 修复 3：接受摩擦不对称，给工程任务「预付摩擦力」

认知类任务（推导、分析）有内在反馈回路，可以靠势能面自然驱动。工程类任务（修复、重构、提取）没有，必须预付：

- **时间盒 + 定义「最小可运行」**：修 reward 不叫「修复 harness」，叫「让 `python demo.py` 打印出一个非零数字」。把目标缩小到 30 分钟内可达，摩擦就降到了可穿越的量级。
- **先做，先做，先做**：P0 任务放在每周第一个工作块，趁「本周还很长」的错觉还没形成之前完成。W29 的教训是 P0 被排进清单后逐日后移，最终被「提前建 W30 文件夹」这种行为绕过。

### 修复 4：给罚则一个非零的 \(C\)

诚实地说：单人系统里不存在真正外部的 \(C\)。但存在**不可逆性**可以借用——git 的不可逆性、公开承诺的不可逆性。最低成本的近似：**罚则必须具体到动作，且动作必须在违反当场就执行过一次的版本**。例如 W30 规则不应是「若违反则 X」，而应是「本周一早上第一件事就是执行 X 的准备动作」。

## 五、对「树」隐喻的修正

上一篇用树干/枝干/树叶描述养分分配。W29 的数据迫使我修正这个模型：**树的隐喻只有势能项，没有动力学项。** 它描述了「应该」的稳态分布，但完全预测不了「实际」的轨迹——实际的轨迹由摩擦、惯性、约束延迟决定。

更准确的模型是一个**带摩擦的约束力学系统**：

- 主干、枝干、树叶 → 势能面 \(V(x)\) 的形状
- 止损线 → 约束 \(g(x) = 0\)，但需要 \(\lambda \neq 0\)
- 复盘 → 测量装置，当前采样周期 7 天，太长
- 「提前建 W30 文件夹」→ 惯性项，系统有自己的动量，不尊重计划

树的回答「把养分给枝干」仍然是对的，但它是不完整对的。完整的回答是：**改造势能面让枝干方向 downhill，同时给约束装上真实的力。**

## 六、结语：第三条随想时不想再写同一篇

这已经是一周内第二次诊断出同一个病灶。W28 复盘说了一遍，上一篇随想说了一遍，W29 用逐帧一致的数据又说了一遍。**如果一个洞察被重复发现三次而系统状态不变，那它不是洞察，是装饰。**

所以这篇随想的验收标准只有一条，且可机械测量：

> **W30 复盘时，`python demo.py` 输出非零 reward，或 RAG #01 的 `.py` 存在且能跑。二者居其一，这篇就算长成了枝干；两者皆无，则承认这个系统当前的真实功能就是生产文档，然后重新讨论要不要接受这一点。**

不再设四条止损线了。一条就够。约束的数量不重要，\(\lambda\) 的大小才重要。
