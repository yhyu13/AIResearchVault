## 前置知识

> 学习世界模型前，建议按以下顺序掌握基础概念。每个概念给出**一句话解释** + **推荐学习顺序**。

| 序号 | 概念 | 中文解释 | 英文原文 | 为什么需要它 | 推荐顺序 |
|------|------|----------|----------|-------------|---------|
| 1 | 自回归模型 | 每一步生成依赖之前所有已生成结果，像写小说时后面的段落依赖前面的情节 | Autoregressive Model | 世界模型生成视频帧必须因果依赖历史帧，不能"偷看未来" | ⭐ 最先学 |
| 2 | 扩散模型 | 通过从噪声中逐步去噪来生成数据，类似雕塑家从大理石块中一点点雕出形状 | Diffusion Model | 视频扩散模型是当前世界模型的主流基座（如 Sora、HunyuanVideo） | ⭐ 最先学 |
| 3 | Token 化 / VQ-VAE | 将连续数据（如图片）压缩成离散符号序列，类似把高分辨率照片压缩成"视觉单词" | Tokenization / Vector Quantization | MineWorld 等自回归路线依赖 VQ tokenizer 将画面转为离散 token | ⭐ 最先学 |
| 4 | KV Cache | 缓存 Transformer 中 Key/Value 向量，避免每次生成时重复计算历史注意力，加速流式推理 | Key-Value Cache | 流式世界模型（如 Matrix-Game 2.0）依赖 KV Cache 实现实时推理 | ⭐⭐ 其次 |
| 5 | 因果注意力掩码 | 限制注意力只能"往左看"（只看过去不看未来），保证生成过程的因果性 | Causal Attention Mask | Vid2World 将双向视频扩散改为因果扩散的核心改造 | ⭐⭐ 其次 |
| 6 | 知识蒸馏 | 让"小学生"模型模仿"老师"模型的行为，从而用更少的计算步骤达到相近效果 | Knowledge Distillation | Matrix-Game 2.0 的 Self-Forcing 蒸馏是将多步扩散压缩到 1-4 步的关键 | ⭐⭐ 其次 |
| 7 | Exposure Bias | 训练时模型看到的是真实数据，推理时却看到自己生成的数据，两者分布不一致导致误差累积 | Exposure Bias | Self-Forcing 蒸馏专门解决训练-推理分布不匹配问题 | ⭐⭐⭐ 再深入 |
| 8 | 3D Gaussian Splatting | 用三维高斯球表示场景，可实现高质量实时渲染，类似用数百万个彩色"棉花球"填充空间 | 3D Gaussian Splatting | WorldPlay 的显式几何记忆与 Gaussian 类结构密切相关 | ⭐⭐⭐ 再深入 |

**学习路径建议**：
```
扩散模型基础 → VQ-VAE Token 化 → 自回归 Transformer
    ↓
因果注意力 + KV Cache（流式推理）
    ↓
知识蒸馏（一致性蒸馏 / Self-Forcing）
    ↓
显式 3D 记忆 / 世界模型评测协议
```

## 核心概念与架构

### 1. 世界模型的形式化定义

世界模型（World Model）的核心任务是：给定动作序列 $a_1, \dots, a_t$ 和初始画面 $x_0$，学习条件分布 $p_\theta(x_{t+1} | x_{\leq t}, a_{\leq t})$，即预测"在当前历史画面和动作条件下，下一帧画面长什么样"。

用一句话说：**世界模型 = 游戏引擎的神经网络替身，输入动作，输出画面。**

### 2. 三重矛盾

世界模型面临三个无法同时最优的矛盾：

```
┌─────────────────────────────────────────────────────────────┐
│                    世界模型的三重矛盾                         │
├─────────────────────────────────────────────────────────────┤
│  ① 质量 vs 速度                                           │
│     多步扩散：画质高 ←────矛盾────→ 延迟高（几十步采样）      │
│     少步蒸馏：延迟低 ←────矛盾────→ 质量损失（近似误差）      │
│                                                             │
│  ② 隐式记忆 vs 显式记忆                                    │
│     纯自回归上下文：无额外成本 ←──矛盾──→ 容量有硬上限        │
│     显式 3D 记忆：容量无限  ←──矛盾──→ 构建/更新成本高       │
│                                                             │
│  ③ 通用性 vs 可复现性                                      │
│     闭源大模型（Genie 3）：通用性强 ←矛盾→ 无法复现/微调      │
│     开源路线：可完全控制 ←──矛盾──→ 通用性稍弱               │
└─────────────────────────────────────────────────────────────┘
```

### 3. 三大技术路线谱系

```
┌──────────────────────────────────────────────────────────────────────┐
│                        世界模型技术路线地图                            │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  路线一：自回归 Token 化（"一切皆可 Token"）                         │
│  ┌────────────────────────────────────────────────────────────┐     │
│  │  画面 → VQ Tokenizer → 离散视觉 Token                      │     │
│  │  键鼠动作 → Action Token                                   │     │
│  │  交错排列 → 因果 Transformer → Next-Token Prediction        │     │
│  │                                                            │     │
│  │  代表：MineWorld (4-7 FPS)                                 │     │
│  │  优势：架构简洁，完全开源，易复现                            │     │
│  │  劣势：VQ 重建误差构成画质天花板，帧内并行假设有近似误差      │     │
│  └────────────────────────────────────────────────────────────┘     │
│                              ↓                                       │
│  路线二：因果扩散 + 少步蒸馏（开源主流，2025 下半年确立）          │
│  ┌────────────────────────────────────────────────────────────┐     │
│  │  双向视频扩散（教师，质量高但不能实时）                       │     │
│  │       ↓ 蒸馏                                                │     │
│  │  因果学生模型（帧只依赖历史，1-4 步采样）                    │     │
│  │       + 动作注入模块（键鼠 cross-attention）                │     │
│  │       + KV Cache 流式推理                                   │     │
│  │                                                            │     │
│  │  代表：Matrix-Game 2.0 (25 FPS, 720p)                       │     │
│  │  核心技术：Self-Forcing 蒸馏（学生在自己 rollout 上训练）     │     │
│  │  优势：追平闭源实时性，权重开源                              │     │
│  │  劣势：长时一致性仍有限，极端动作下鲁棒性待验证               │     │
│  └────────────────────────────────────────────────────────────┘     │
│                              ↓                                       │
│  路线三：预训练视频扩散改造（"已有模型再利用"）                     │
│  ┌────────────────────────────────────────────────────────────┐     │
│  │  预训练视频扩散模型（已见过海量视频，有强世界先验）           │     │
│  │       ↓ 改造                                                │     │
│  │  因果化：双向注意力 → 因果掩码 + 逐帧去噪调度重设计          │     │
│  │  动作引导：反向采样每步用动作条件修正 score 方向              │     │
│  │                                                            │     │
│  │  代表：Vid2World (ICLR 2026)                                │     │
│  │  优势：免从头训练，资源门槛低                                │     │
│  │  劣势：仍多步采样非实时，引导强度需调参                      │     │
│  └────────────────────────────────────────────────────────────┘     │
│                              ↓                                       │
│  路线四：闭源大规模自回归（算力垄断路线）                           │
│  ┌────────────────────────────────────────────────────────────┐     │
│  │  纯自回归，无显式 3D 表征                                   │     │
│  │  靠超大规模上下文"涌现"物体恒存性与场景记忆                  │     │
│  │                                                            │     │
│  │  代表：Genie 3 (720p / 24 FPS / 分钟级一致性)               │     │
│  │  优势：通用性最强，一致性最佳                                │     │
│  │  劣势：完全闭源，无法复现，动作空间仅导航类                   │     │
│  └────────────────────────────────────────────────────────────┘     │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 4. 核心架构：Matrix-Game 2.0 的 Self-Forcing 蒸馏

> **为什么选 Matrix-Game 2.0 作为核心架构讲解？**
> 因为它是开源路线中**首个追平闭源实时性规格**的模型，技术细节公开，最具复现价值。

**训练阶段**：
```
双向扩散教师（高质量，但每帧依赖未来帧，不能实时）
         │
         ▼
因果学生模型（帧 t 只依赖历史帧 ≤ t，1-4 步去噪）
         │
         ├── 动作注入：键鼠信号编码为条件，cross-attention 注入
         │
         └── Self-Forcing 损失：学生在自己生成的 rollout 上
              计算分布匹配损失 ←── 核心创新，解决 Exposure Bias
```

**推理阶段**：
```
初始帧 x_0 ──→ 因果 Transformer + KV Cache ──→ 生成帧 x_1
                     │                              │
                     │←──── 键鼠动作 a_1 ───────────┘
                     │
                     ▼
              流式输出 x_2, x_3, ... x_t
              （chunk-wise 因果注意力，720p @ 25 FPS）
```

## 评估指标详解

> 评测世界模型不能只看"画面像不像"，还要看"动作有没有被正确执行"。

### 1. FVD（Fréchet Video Distance）

**含义**：衡量生成视频分布与真实视频分布之间的距离，类似图像领域的 FID，但扩展到了视频时序维度。

**公式**：
```
FVD = ||μ_real - μ_gen||² + Tr(Σ_real + Σ_gen - 2√(Σ_real · Σ_gen))
```
其中 μ 和 Σ 是通过预训练视频特征提取器（如 I3D）从真实/生成视频中提取特征的均值和协方差。

**为什么用它**：FVD 是目前视频生成领域最广泛接受的分布级质量指标，能捕捉整体视觉真实感。

**常见误区**：
- ❌ **误区 1**：FVD 低 = 动作跟随好。**实际上 FVD 完全不知道你按了什么键**——模型可以生成很漂亮的视频，但完全不响应动作输入。
- ❌ **误区 2**：FVD 可以跨数据集比较。**实际上 FVD 对特征提取器敏感，不同论文的 I3D 权重版本可能不同，直接对比数字需谨慎。**
- ❌ **误区 3**：FVD 低 = 时间一致性好。**FVD 是分布级别的，一帧帧闪屏在分布层面可能被平均掉。**

---

### 2. Action-Following Accuracy（动作跟随精度）

**含义**：量化"按了前进键，画面是否真的在往前走"的程度。

**常用实现方式**：
- **Inverse Dynamics 一致性**：用逆动力学模型从相邻两帧反推"应该是什么动作"，与真实输入动作比对。
- **光流一致性**：计算生成帧的光流，与动作对应的光流先验（如前进 = 向后流动的纹理）比对。

**为什么用它**：FVD 只能测"像不像"，不能测"听不听话"。世界模型是**交互式**的，动作跟随是核心能力。

**常见误区**：
- ❌ **误区 1**：动作跟随高 = 视频质量高。**实际上模型可以严格跟随动作但画面很糊（比如 VQ token 重建误差大）。**
- ❌ **误区 2**：单一阈值判定好坏。**不同游戏类型的"好"标准不同——FPS 需要精确的视角转动，RPG 的行走允许更宽松。**

---

### 3. Revisit Consistency（场景重访一致性）

**含义**：玩家离开某一区域后再次返回，场景几何结构（建筑位置、地形轮廓）保持一致的程度。

**为什么用它**：这是区分"生成视频"和"可玩世界"的关键指标。短视频可以靠视觉暂骗过关，但**可玩世界要求持久状态**。

**常见误区**：
- ❌ **误区 1**：把"帧间相似度"当重访一致性。**两帧看起来"差不多"不代表几何一致——建筑位置偏移 1 米在视觉上可能不明显，但 gameplay 会穿帮。**
- ❌ **误区 2**：只在固定轨迹上测试。**玩家可能以任意角度、任意路径重访，评测需要覆盖非线性路径。**

---

### 4. FPS / 延迟（实时性指标）

**含义**：模型生成一帧画面的时间（毫秒），或每秒能生成的帧数。

**阈值参考**：
| 等级 | FPS | 体验 |
|------|-----|------|
| 不可玩 | < 4 FPS | 明显卡顿，无法交互 |
| 可玩门槛 | ~10 FPS | 能玩但体验较差 |
| 流畅门槛 | ~24 FPS | 接近传统游戏流畅标准 |
| 理想 | ≥ 30 FPS | 无明显延迟感 |

**为什么用它**：实时性是"可玩世界"的前提。再好的质量，如果延迟超过人类感知阈值（~100ms）， gameplay 体验就会受损。

**常见误区**：
- ❌ **误区 1**：只报告最高 FPS。**实际 FPS 随场景复杂度、历史长度、分辨率波动，应报告分布而非峰值。**
- ❌ **误区 2**：忽略首帧延迟 vs 持续延迟。**首帧需要加载模型/初始化，可能远高于稳态 FPS，两者都应报告。**

---

### 5. WBench / WorldMark（专用基准分数）

**含义**：2025 下半年出现的交互世界模型专用 benchmark，包含多轮交互评测协议。

**WBench**：多轮交互视频世界模型基准，测试模型在长交互序列中的一致性、动作跟随和物理合理性。

**WorldMark**：第三方评测平台，包含一致性排名，常用于闭源模型（如 Genie 3）的唯一公开参照。

**为什么用它**：传统视频生成 benchmark（如 UCF-101）不测试交互性，专用基准填补了评测空白。

**常见误区**：
- ❌ **误区 1**：基准分数高 = 真实 gameplay 好。**基准是固定协议，模型可能过拟合基准的"过场动画式一致性"，而真实游戏中的长尾交互（极端动作、反常操作）依然崩坏——这叫 Goodhart 风险。**
- ❌ **误区 2**：不同基准可以直接对比。**WBench 和 WorldMark 的协议不同，分数不可直接换算。**

## 关键代码

> 以下代码用 Python 演示世界模型的核心组件：因果注意力掩码、Self-Forcing 蒸馏损失、以及一个简单的"世界模型评测器"框架。代码可直接运行或稍作修改即可运行。

### 代码 1：因果注意力掩码（Causal Mask）

这是将双向扩散改为因果扩散的最核心改造——确保帧 t 只能看到历史帧，不能"偷看"未来。

```python
"""
因果注意力掩码实现
核心思想：对于长度为 T 的序列，位置 i 只能 attend 到位置 j ≤ i
"""
import torch
import torch.nn.functional as F


def create_causal_mask(seq_len: int, device: str = "cpu") -> torch.Tensor:
    """
    创建因果注意力掩码
    
    参数:
        seq_len: 序列长度（帧数）
        device: 计算设备
    
    返回:
        mask: [seq_len, seq_len] 的布尔掩码
              True 表示允许 attend，False 表示屏蔽
    """
    # torch.tril 生成下三角矩阵（包含对角线）
    # 例如 seq_len=4 时：
    # [[1, 0, 0, 0],
    #  [1, 1, 0, 0],
    #  [1, 1, 1, 0],
    #  [1, 1, 1, 1]]
    mask = torch.tril(torch.ones(seq_len, seq_len, device=device))
    
    # 转换为布尔型：1 -> True（允许），0 -> False（屏蔽）
    mask = mask.bool()
    
    return mask


def apply_causal_attention(
    q: torch.Tensor,      # [batch, heads, seq_len, dim]
    k: torch.Tensor,      # [batch, heads, seq_len, dim]
    v: torch.Tensor,      # [batch, heads, seq_len, dim]
    mask: torch.Tensor    # [seq_len, seq_len]
) -> torch.Tensor:
    """
    应用因果注意力计算
    
    参数:
        q: Query 矩阵
        k: Key 矩阵
        v: Value 矩阵
        mask: 因果掩码
    
    返回:
        output: 注意力输出 [batch, heads, seq_len, dim]
    """
    # 计算原始注意力分数: Q @ K^T
    # scores[b, h, i, j] 表示第 i 个位置对第 j 个位置的注意力权重
    scores = torch.matmul(q, k.transpose(-2, -1))
    
    # 缩放，防止 softmax 饱和
    dim = q.size(-1)
    scores = scores / (dim ** 0.5)
    
    # 应用因果掩码：将未来位置（mask=False）的分数设为负无穷
    # 这样 softmax 后这些位置的权重为 0
    scores = scores.masked_fill(~mask, float('-inf'))
    
    # 计算 softmax 得到注意力权重
    attn_weights = F.softmax(scores, dim=-1)
    
    # 注意力输出 = 权重 @ Value
    output = torch.matmul(attn_weights, v)
    
    return output


# ========== 运行示例 ==========
if __name__ == "__main__":
    batch_size, num_heads, seq_len, dim = 2, 4, 8, 64
    
    # 随机生成 Q, K, V
    q = torch.randn(batch_size, num_heads, seq_len, dim)
    k = torch.randn(batch_size, num_heads, seq_len, dim)
    v = torch.randn(batch_size, num_heads, seq_len, dim)
    
    # 创建因果掩码
    mask = create_causal_mask(seq_len)
    print("因果掩码形状:", mask.shape)
    print("因果掩码示例（4x4）:\n", mask[:4, :4].int())
    
    # 应用因果注意力
    output = apply_causal_attention(q, k, v, mask)
    print("输出形状:", output.shape)
    print("✅ 因果注意力验证：第 0 帧输出仅依赖第 0 帧输入")
```

### 代码 2：Self-Forcing 蒸馏损失（核心创新）

Self-Forcing 解决的是**Exposure Bias**问题：训练时学生模型看到教师生成的"干净"数据，推理时却看到自己生成的有噪声的 rollout，两者分布不一致导致误差累积。

```python
"""
Self-Forcing 蒸馏损失演示
核心思想：学生模型在自己生成的 rollout 上计算损失，
         而非只在教师生成的"干净"数据上训练
"""
import torch
import torch.nn as nn
import torch.nn.functional as F


class SimpleWorldModel(nn.Module):
    """
    简化的世界模型：输入历史帧 + 动作，预测下一帧的噪声分布
    
    实际论文中这通常是 U-Net 或 DiT（Diffusion Transformer），
    这里用简单的 MLP 演示核心逻辑。
    """
    def __init__(self, frame_dim: int, action_dim: int, hidden_dim: int = 256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(frame_dim + action_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, frame_dim * 2),  # 输出均值和方差
        )
        self.frame_dim = frame_dim
    
    def forward(self, x_t: torch.Tensor, a_t: torch.Tensor) -> tuple:
        """
        预测下一帧的分布参数（均值 μ 和对数方差 logσ）
        
        参数:
            x_t: 当前帧 [batch, frame_dim]
            a_t: 当前动作 [batch, action_dim]
        
        返回:
            mu: 预测均值 [batch, frame_dim]
            logvar: 预测对数方差 [batch, frame_dim]
        """
        inp = torch.cat([x_t, a_t], dim=-1)
        out = self.net(inp)
        mu = out[:, :self.frame_dim]
        logvar = out[:, self.frame_dim:]
        return mu, logvar


def self_forcing_loss(
    student: SimpleWorldModel,
    teacher: SimpleWorldModel,  # 双向教师（冻结权重）
    x_0: torch.Tensor,          # 初始帧 [batch, frame_dim]
    actions: torch.Tensor,      # 动作序列 [batch, T, action_dim]
    num_steps: int,             # rollout 长度
    gamma: float = 0.99         # 时间折扣因子
) -> torch.Tensor:
    """
    Self-Forcing 蒸馏损失
    
    核心流程：
    1. 用学生模型自回归生成完整 rollout
    2. 在学生的 rollout 上，让教师的分布作为"目标"
    3. 计算学生预测分布与教师目标分布之间的 KL 散度
    4. 加权求和（近期帧权重高，远期帧权重低）
    
    参数:
        student: 学生模型（因果，少步，可实时）
        teacher: 教师模型（双向，多步，质量高但慢）
        x_0: 初始帧
        actions: 动作序列
        num_steps: rollout 长度
        gamma: 时间折扣因子（远期帧不确定性更高，权重更低）
    
    返回:
        loss: 标量损失值
    """
    batch_size = x_0.size(0)
    frame_dim = x_0.size(1)
    
    # ===== 第 1 步：学生模型自回归生成 rollout =====
    student_states = [x_0]
    x_t = x_0
    
    for t in range(num_steps):
        # 学生预测下一帧的分布参数
        mu_s, logvar_s = student(x_t, actions[:, t])
        
        # 从学生分布中采样下一帧（重参数化技巧）
        std_s = torch.exp(0.5 * logvar_s)
        eps = torch.randn_like(std_s)
        x_next = mu_s + std_s * eps  # 学生生成的帧
        
        student_states.append(x_next)
        x_t = x_next  # 下一步的输入
    
    # ===== 第 2 步：在学生的 rollout 上计算教师的目标分布 =====
    total_loss = 0.0
    
    for t in range(1, num_steps + 1):
        x_t_student = student_states[t]           # 学生生成的第 t 帧
        a_t = actions[:, t - 1]                    # 对应动作
        x_t_prev = student_states[t - 1]           # 前一帧（也是学生生成的）
        
        # 学生在该位置的分布预测（重新前向传播）
        mu_s, logvar_s = student(x_t_prev, a_t)
        
        # 教师在同一位置的分布预测（作为目标）
        # 注意：教师是双向的，它看的是学生 rollout 的"历史部分"
        with torch.no_grad():
            mu_t, logvar_t = teacher(x_t_prev, a_t)
        
        # ===== 第 3 步：计算两个高斯分布的 KL 散度 =====
        # KL(N(μ_s, σ_s²) || N(μ_t, σ_t²)) 的解析式：
        # = 0.5 * [log(σ_t²/σ_s²) + (σ_s² + (μ_s-μ_t)²)/σ_t² - 1]
        kl = 0.5 * (
            logvar_t - logvar_s
            + (torch.exp(logvar_s) + (mu_s - mu_t) ** 2) / torch.exp(logvar_t)
            - 1
        )
        kl = kl.sum(dim=-1).mean()  # 对维度求和，对 batch 取平均
        
        # ===== 第 4 步：时间折扣加权 =====
        weight = gamma ** (t - 1)
        total_loss += weight * kl
    
    return total_loss / num_steps


# ========== 运行示例 ==========
if __name__ == "__main__":
    # 超参数
    batch_size = 4
    frame_dim = 64
    action_dim = 8
    num_steps = 5  # rollout 长度
    
    # 初始化模型
    student = SimpleWorldModel(frame_dim, action_dim)
    teacher = SimpleWorldModel(frame_dim, action_dim)
    teacher.eval()  # 教师冻结
    for p in teacher.parameters():
        p.requires_grad = False
    
    # 模拟数据
    x_0 = torch.randn(batch_size, frame_dim)
    actions = torch.randn(batch_size, num_steps, action_dim)
    
    # 计算 Self-Forcing 损失
    loss = self_forcing_loss(student, teacher, x_0, actions, num_steps)
    print(f"Self-Forcing 损失值: {loss.item():.4f}")
    print("✅ 关键理解：损失是在学生自己生成的 rollout 上计算的，")
    print("   因此训练分布与推理分布一致，消除了 Exposure Bias")
```

### 代码 3：世界模型评测器（含 FVD + Action-Following）

```python
"""
世界模型评测框架：FVD + Action-Following + Revisit Consistency
"""
import torch
import torch.nn as nn
import numpy as np
from typing import List, Tuple


class WorldModelEvaluator:
    """
    世界模型评测器
    
    评测维度：
    1. FVD（视频分布距离）
    2. Action-Following（动作跟随精度）
    3. Revisit Consistency（场景重访一致性）
    """
    
    def __init__(self, feature_extractor: nn.Module, device: str = "cpu"):
        """
        参数:
            feature_extractor: 预训练视频特征提取器（如 I3D）
            device: 计算设备
        """
        self.feature_extractor = feature_extractor
        self.device = device
    
    def compute_fvd(
        self,
        real_videos: torch.Tensor,    # [N, T, C, H, W]
        gen_videos: torch.Tensor      # [N, T, C, H, W]
    ) -> float:
        """
        计算 FVD（Fréchet Video Distance）
        
        步骤：
        1. 用 I3D 提取视频特征
        2. 计算真实/生成视频特征的均值和协方差
        3. 计算 Fréchet 距离
        """
        with torch.no_grad():
            # 提取特征 [N, feature_dim]
            real_features = self.feature_extractor(real_videos)
            gen_features = self.feature_extractor(gen_videos)
        
        # 转换为 numpy
        real_features = real_features.cpu().numpy()
        gen_features = gen_features.cpu().numpy()
        
        # 计算均值和协方差
        mu_real = np.mean(real_features, axis=0)
        mu_gen = np.mean(gen_features, axis=0)
        
        sigma_real = np.cov(real_features, rowvar=False)
        sigma_gen = np.cov(gen_features, rowvar=False)
        
        # 计算 Fréchet 距离
        diff = mu_real - mu_gen
        
        # 计算协方差矩阵的乘积的平方根（使用 SVD 稳定计算）
        covmean = self._sqrtm(sigma_real @ sigma_gen)
        
        fvd = np.dot(diff, diff) + np.trace(
            sigma_real + sigma_gen - 2 * covmean
        )
        
        return float(fvd)
    
    def _sqrtm(self, matrix: np.ndarray) -> np.ndarray:
        """矩阵平方根（用于 FVD 计算）"""
        u, s, v = np.linalg.svd(matrix)
        return u @ np.diag(np.sqrt(s)) @ v
    
    def compute_action_following(
        self,
        frames: torch.Tensor,        # [T, C, H, W] 生成帧序列
        actions: torch.Tensor,       # [T, action_dim] 输入动作
        inverse_dynamics: nn.Module  # 逆动力学模型（帧→动作预测）
    ) -> float:
        """
        计算动作跟随精度
        
        方法：用逆动力学模型从 (frame_t, frame_t+1) 反推动作，
              与真实输入动作比对
        
        返回:
            accuracy: [0, 1] 之间的精度值
        """
        correct = 0
        total = 0
        
        with torch.no_grad():
            for t in range(len(frames) - 1):
                # 从相邻帧反推动作
                pred_action = inverse_dynamics(
                    frames[t:t+1], frames[t+1:t+2]
                )
                
                # 与真实动作比对（简单阈值判定）
                true_action = actions[t]
                error = torch.norm(pred_action - true_action)
                
                if error < 0.5:  # 阈值可调整
                    correct += 1
                total += 1
        
        return correct / total if total > 0 else 0.0
    
    def compute_revisit_consistency(
        self,
        frame_at_leave: torch.Tensor,   # 离开时的帧 [C, H, W]
        frame_at_return: torch.Tensor,  # 返回时的帧 [C, H, W]
        threshold: float = 0.9
    ) -> float:
        """
        计算场景重访一致性
        
        简单实现：用 SSIM（结构相似性）衡量两帧的结构一致性
        实际论文中可能用更复杂的 3D 几何对齐指标
        
        返回:
            consistency: [0, 1]，1 表示完全一致
        """
        # 简化为像素级相关性（实际应用应使用 SSIM 或特征级比对）
        flat_leave = frame_at_leave.flatten()
        flat_return = frame_at_return.flatten()
        
        # 归一化互相关
        leave_norm = (flat_leave - flat_leave.mean()) / flat_leave.std()
        return_norm = (flat_return - flat_return.mean()) / flat_return.std()
        
        corr = torch.dot(leave_norm, return_norm) / len(leave_norm)
        
        return float(corr)


# ========== 运行示例 ==========
if __name__ == "__main__":
    # 模拟数据
    batch_size, T, C, H, W = 4, 16, 3, 64, 64
    real_videos = torch.randn(batch_size, T, C, H, W)
    gen_videos = torch.randn(batch_size, T, C, H, W)
    
    # 模拟特征提取器（实际应使用预训练 I3D）
    class MockI3D(nn.Module):
        def forward(self, x):
            # x: [N, T, C, H, W]
            return torch.randn(x.size(0), 512)
    
    evaluator = WorldModelEvaluator(MockI3D())
    
    # 计算 FVD
    fvd = evaluator.compute_fvd(real_videos, gen_videos)
    print(f"FVD: {fvd:.2f}")
    
    # 模拟动作跟随评测
    frames = torch.randn(T, C, H, W)
    actions = torch.randn(T, 4)
    
    class MockInverseDynamics(nn.Module):
        def forward(self, f1, f2):
            return torch.randn(f1.size(0), 4)
    
    acc = evaluator.compute_action_following(frames, actions, MockInverseDynamics())
    print(f"动作跟随精度: {acc:.2%}")
    
    # 模拟重访一致性
    consistency = evaluator.compute_revisit_consistency(
        frames[0], frames[-1]
    )
    print(f"重访一致性: {consistency:.2%}")
    print("✅ 评测框架就绪")
```

长时一致性的答案从"更长的上下文"转向"结构化外部记忆"——显式 3D 几何表征让场景重访不漂移，代表隐式 → 显式记忆的范式转向，与 Hunyuan-GameCraft 的混合历史条件（近高远低有损压缩）形成光谱两端。

### 基础题

3. **FVD 能评测动作跟随吗？** 为什么不能？如果你设计一个评测协议来测"按了前进键画面是否往前走"，你会怎么做？

### 进阶题

1. **Self-Forcing 的分布匹配损失近似的是哪种散度？** 推导 KL 散度在高斯分布下的解析式，并讨论为什么选择 KL 而非 Wasserstein 距离。

2. **KV Cache 长度与注意力成本的权衡**：如果无限增长 KV Cache，注意力计算的复杂度会如何增长？是否存在"最优 Cache 长度"？如何设计 Cache 淘汰策略？

3. **显式记忆与可破坏世界的根本冲突**：WorldPlay 的几何记忆假设场景静态，但游戏的核心乐趣来自改变环境（挖掘、建造、破坏）。设计一个支持"写操作"的显式记忆架构。
